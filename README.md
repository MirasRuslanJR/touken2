# ТАМЫР — находим корень, а не симптом

AI-платформа персонализированного образования для школьников Казахстана 7–12
классов. Каждый предмет описан графом знаний (микротемы + связи «что от чего
зависит»); когда ученик ошибается, платформа спускается вниз по графу и находит
настоящую причину, а не очередной симптом.

## Запуск за 10 секунд

Открой `index.html` двойным кликом — во **Firefox** это полностью работает
из коробки. В **Chrome/Edge** браузер блокирует `fetch()` ES-модулей с
`file://` политикой CORS (это ограничение браузера, не платформы — сборки
здесь по-прежнему нет и не будет). Для Chrome/Edge подними любой статический
сервер без единого шага сборки:
```
npx serve .
# или
python -m http.server 8080
```
Это не npm-сборка — `serve`/`http.server` ничего не компилируют, они просто
раздают уже готовые файлы по HTTP вместо `file://`. Это же нужно для Service
Worker/PWA (офлайн-режим) — он тоже не регистрируется на `file://` по
спецификации.

При первом запуске `config.js` ещё не существует. Скопируй `.env.example` в
`.env`, оставь `FORCE_DEMO=true` — и всё, включая AI-функции, будет работать в
демо-режиме без интернета и без регистрации. Кнопки **«Демо: ученик»** и
**«Демо: учитель»** сразу заводят в заполненный аккаунт с настоящей историей.

## Секреты: .env → config.js

`config.js` **генерируется**, его никогда не редактируют и не коммитят
(оба файла в `.gitignore`). Источник правды — `.env`:

```
cp .env.example .env      # один раз
# впиши реальные SUPABASE_URL / SUPABASE_ANON_KEY / GEMINI_API_KEY
node scripts/gen-config.mjs   # после каждого изменения .env
```

- `GEMINI_API_KEY` в `.env` — только для локальной разработки. На билде для
  Render (`render-build.sh`) это поле всегда пишется пустым, потому что
  статический сайт не может спрятать ключ от `view-source` — реальный ключ
  живёт только как секрет Supabase Edge Function.
- `SUPABASE_URL`/`SUPABASE_ANON_KEY` можно спокойно показывать публично — это
  расчитано на клиентский доступ, безопасность обеспечивает RLS в
  `data/schema.sql`, не секретность анонимного ключа.

## Подключение реального Supabase + Gemini

1. Создай проект на supabase.com, выполни `data/schema.sql`, затем
   `data/seed.sql` в SQL Editor.
2. Если проект уже существует и словил `infinite recursion detected in policy
   for relation "classes"` — выполни `data/fix_rls_recursion.sql` один раз
   (в новых проектах этот баг уже не воспроизводится, `schema.sql` его чинит
   заранее).
3. Впиши `SUPABASE_URL`/`SUPABASE_ANON_KEY` в `.env`, поставь `FORCE_DEMO=false`,
   прогони `node scripts/gen-config.mjs`.
4. Для реального ИИ на **публичном** деплое — задеплой Edge Function:
   `supabase functions deploy ai`, затем `supabase secrets set
   GEMINI_API_KEY=...` (ключ никогда не попадает в браузер — все вызовы
   Gemini идут через эту функцию). Локально можно проще: держать
   `GEMINI_API_KEY` прямо в `.env` — он не покидает машину, раз `config.js`
   не коммитится.
5. Создай демо-пользователей через Supabase Auth (Dashboard → Authentication),
   затем вставь строки в `profiles` с их `id` (см. комментарий в конце
   `seed.sql`).
6. Задеплой статику на Render/Netlify/Vercel — Build Command указывает на
   `render-build.sh` (или его логику), который пишет `config.js` из
   переменных окружения хостинга, а не из локального `.env`.

## Выбор модели

Используется **`gemini-3.5-flash-lite`**. Это осознанный выбор по замерам на
настоящих промптах этого приложения, а не экономия на качестве:

| | 3.5-flash-lite | 3.5-flash | 3.6-flash |
|---|---|---|---|
| Конструктор модуля (10 заданий) | **5.4 с** | 16.8 с | 19-60 с |
| Остальные функции | **~1 с** | 4-7 с | 20-40 с |
| Качество на этих задачах | не хуже | не хуже | не хуже |
| Устойчивость к атаке на промпт | отбита | отбита | отбита |
| Дневной лимит free tier | высокий | ниже | ~20 запросов |

Проверялось: полнота модуля (10 заданий, все 5 уровней, с ответами и разборами),
поиск реальной ошибки в объяснении ученика, вопрос по логике а не по числу,
казахский вывод, отказ выдать ответ при прямой попытке взлома промпта. По всем
пунктам lite не уступает, но отвечает в 10-30 раз быстрее — для живого показа
это решающе.

`gemini-2.5-flash` и `gemini-2.5-flash-lite` больше не существуют (404).

## Надёжность ИИ на бесплатном тарифе

Бесплатный тариф Gemini ограничен по числу запросов в день, поэтому весь слой
ИИ (`assets/js/ai.js`) построен так, чтобы лимит нельзя было выжечь случайно, а
исчерпание лимита не выглядело как поломка:

- **Дневной бюджет.** `AI_DAILY_BUDGET` — клиентский предохранитель, а не
  реальный потолок провайдера: он нужен, чтобы случайный цикл не слил дневную
  квоту незаметно. Когда бюджет кончился, каждая функция мгновенно отдаёт
  заготовленный офлайн-ответ вместо запроса.
- **429 никогда не ретраится.** Повтор при исчерпанной квоте только сжигал бы
  ещё один запрос из уже пустого лимита. Ретраится только транзиентная ошибка
  (5xx, обрыв сети), и только если первая попытка упала быстро.
- **Кэш по содержимому.** Ключ = функция + payload + язык + хэш изображения.
  Повторный вопрос стоит 0 запросов. Язык в ключе нужен, чтобы казахский экран
  не проигрывал русский ответ; хэш изображения — чтобы два разных фото тетради
  не схлопывались в одну запись кэша.
- **Дедупликация параллельных вызовов.** Три одновременных одинаковых запроса
  (двойной клик, два виджета на экране) разделяют один промис и стоят один
  запрос, а не три.
- **Таймауты по функциям.** Выставлены по замерам плюс широкий запас на
  венное wifi: `module_builder` 45 c, `scan_notebook` 40 c, остальные 20-30 c.
- **Проверка «понял или угадал»** запускается только там, где угадать реально
  можно (варианты ответа) или ответ пришёл подозрительно быстро, а не после
  каждого верного ответа.
- **Честная маркировка.** Каждая ИИ-панель помечена бейджем источника: живой
  Gemini, кэш, офлайн-резерв или исчерпанный лимит. Заготовленный ответ никогда
  не выдаётся за ответ модели. В боковой панели виден остаток дневного лимита.
- **Язык.** Директива языка подмешивается в системный промпт, поэтому при
  казахском интерфейсе ИИ отвечает по-казахски.

Для репетиции перед показом: `FORCE_DEMO_AI=true` в `.env` — все ИИ-функции
отвечают заготовками, лимит не тратится вообще, бэкенд при этом остаётся
настоящим.

## Архитектура

Чистый HTML5 + CSS3 + vanilla JS (ES-модули). Никаких фреймворков, сборщиков
или npm-зависимостей во фронтенде.

```
index.html          лендинг + живой граф + вход (демо/email)
app.html             оболочка приложения (hash-роутер, боковая навигация)
assets/css/          tokens → base → components → views → graph
assets/js/
  main.js            точка входа app.html: сессия, роль, роутинг, офлайн-индикатор
  landing.js          точка входа index.html: демо-граф, вход
  router.js            hash-роутинг + View Transitions API
  store.js              минимальное состояние без библиотек
  db.js                  единственная точка входа в Supabase (+ демо-фолбэк)
  demo-data.js            встроенный датасет для ?demo=1 / FORCE_DEMO
  ai.js                    единственная точка входа в Gemini: схемы, таймаут,
                           ретрай, IndexedDB-кэш, офлайн-фолбэки
  graph.js                  рендер графа (SVG, pan/zoom, drag), поиск корня,
                             волна подсветки при закрытии пробела
  mastery.js                 расчёт mastery, адаптивная сложность, риск-скор
  offline.js                  IndexedDB кэш + очередь синхронизации
  i18n.js / a11y.js            RU/KK/EN, режимы доступности
  views/*.js                    13 экранов приложения
data/
  schema.sql              таблицы + RLS
  seed.sql                 граф знаний (52 узла, 65 рёбер) + 62 задания
supabase/functions/ai/     Deno Edge Function — прокси к Gemini 3.5 Flash Lite
```

## Схема БД

`profiles · subjects · nodes · edges · tasks · attempts · mastery · diagnostics
· goals · classes · class_members · scans · ai_events` — см. `data/schema.sql`
для полей и RLS-политик. Ядро графа — таблица `edges`
(`prerequisite_node_id → dependent_node_id`); `graph.js#findRootGap` обходит её
в обратную сторону от узла, где ученик ошибся, пока не найдёт самый глубокий
неосвоенный предок.

## Тестовые данные

- **Граф знаний**: Математика (26 узлов, 31 ребро, 7–9 класс) и Физика
  (26 узлов, 34 ребра, 7–9 класс) — `data/seed.sql`.
- **Задания**: 62 реальных задания с решениями, 5 уровней сложности, по 3
  темам на предмет с полным покрытием (мин. 8 заданий/тема) плюс задания на
  ключевых узлах-предпосылках для диагностики.
- **Демо-ученик**: 44 попытки за последние ~5 дней, mastery по 26+ узлам,
  намеренный скрытый пробел в «Свойства степеней» (`ALG-7-05`), из-за
  которого «Показательные выражения» (`ALG-9-04`) выглядят непонятыми —
  ровно тот сценарий, который показывает экран «Рентген».
- **Демо-класс**: 12 синтетических учеников с разбросом точности/активности
  для тепловой карты и радара риска.
- Все демо-данные генерируются в памяти (`demo-data.js`) — в репозитории нет
  бинарных фикстур.

## Что реализовано

Обязательный каркас A–H: лендинг с живым графом, онбординг, адаптивная
диагностика, экран «Рентген», модули с заданиями, личный кабинет, панель
учителя с тепловой картой, обратная связь по заданиям.

7 киллер-фич: рентген тетради (фото → JSON с точной строкой ошибки), офлайн
PWA с очередью синхронизации, Сократ (тьютор без готовых ответов), детектор
«понял или угадал», режим Фейнмана (Web Speech API), радар учителя, учитель-
мультипликатор (текст → готовый модуль).
