# ТАМЫР

> Платформа, которая ищет причину пробела в знаниях, а не его симптом.
> Future Minds Hackathon · команда touken.

Главные пользователи — **школьник 7–12 класса** и **его учитель**. Каждый предмет
описан не списком тем, а **графом зависимостей**: какая тема на какой стоит.
Когда ученик ошибается, система не подсовывает ещё десять задач по той же теме —
она спускается вниз по графу и находит самый глубокий непонятый узел. Он и есть
**тамыр**, корень.

Пример из демо-данных: у ученика 18% по «Показательным выражениям» (9 класс) —
это видят все. А причина в «Свойствах степеней» (7 класс), где у него 68%. Это
четвёрка, её никто никогда не пойдёт проверять.

## Как это работает

1. Ученик проходит **адаптивную диагностику** — каждый следующий вопрос
   выбирается по предыдущему ответу. Ошибся — система проверяет то, на чём эта
   тема стоит.
2. Открывается экран **«Рентген»**: граф со всеми пробелами, стрелка на корневой
   узел и объяснение от ИИ человеческим языком, почему сломалось именно там.
3. Ученик закрывает корневой пробел заданиями. **Сложность подстраивается** по
   ходу, а после верного ответа на угадываемый вопрос ИИ проверяет, понял он или
   попал наугад.
4. По любой теме доступны **Сократ** (тьютор, который принципиально не даёт
   готовых ответов), **режим Фейнмана** (объясни своими словами вслух — ИИ
   покажет карту понимания) и **скан тетради** (фото решения → точная строка с
   ошибкой).
5. Учитель видит **тепловую карту класса**, которая за секунду отвечает: это один
   отстающий ребёнок или тему провалил весь класс. **Радар риска** называет, кто
   теряет тему прямо сейчас. **Учитель-мультипликатор** превращает текст
   параграфа в готовый модуль с 10 заданиями.

## Технологии

- **Frontend:** HTML5, CSS3, vanilla JavaScript (ES-модули). Никаких фреймворков,
  сборщиков и npm-зависимостей — **ноль шагов сборки**.
- **Backend:** Supabase — PostgreSQL, Auth, Row Level Security, Edge Function на Deno.
- **ИИ:** Gemini 3.5 Flash Lite; при исчерпании лимита — автоматическое
  переключение на любой OpenAI-совместимый провайдер (Groq, OpenRouter, Cerebras).
- **Офлайн:** Service Worker (кэш оболочки) + IndexedDB (кэш данных и очередь
  синхронизации).
- **Граф:** собственный рендер на SVG — раскладка, pan/zoom, поиск корня.
  Внешних библиотек графов нет.

## Запуск

### 1. Быстрый старт — демо без интернета и регистрации

Открой `index.html` двойным кликом — во **Firefox** работает из коробки. В
**Chrome/Edge** браузер блокирует ES-модули с `file://` по CORS, поэтому подними
любой статический сервер:

```bash
npx serve .
# или
python -m http.server 8080
```

Это не сборка — сервер ничего не компилирует, просто раздаёт готовые файлы по
HTTP вместо `file://`. То же нужно для Service Worker: по спецификации он не
регистрируется на `file://`.

Скопируй `.env.example` в `.env` и оставь `FORCE_DEMO=true`:

```bash
cp .env.example .env
node scripts/gen-config.mjs
```

Кнопки **«Демо: ученик»** и **«Демо: учитель»** сразу заводят в заполненный
аккаунт с настоящей историей. ИИ в этом режиме отвечает заготовками — интернет
не нужен вообще.

### 2. Секреты: `.env` → `config.js`

Браузер не умеет читать `.env`, а сборки здесь нет. Поэтому `config.js`
**генерируется** скриптом и никогда не редактируется руками. Оба файла в
`.gitignore` — в репозиторий не попадают.

```bash
cp .env.example .env          # один раз
# впиши SUPABASE_URL / SUPABASE_ANON_KEY / GEMINI_API_KEY
node scripts/gen-config.mjs   # после каждого изменения .env
```

| Переменная | Зачем |
|---|---|
| `SUPABASE_URL`, `SUPABASE_ANON_KEY` | Можно показывать публично — они рассчитаны на клиент, безопасность держит RLS |
| `GEMINI_API_KEY` | **Только для локальной разработки.** В публичный билд не попадает — см. шаг 4 |
| `GEMINI_MODEL` | По умолчанию `gemini-3.5-flash-lite` |
| `FORCE_DEMO` | `true` — встроенный датасет, `false` — настоящий Supabase |
| `FORCE_DEMO_AI` | `true` — ИИ отвечает заготовками, лимит не тратится. Для репетиции показа |
| `AI_DAILY_BUDGET` | Клиентский предохранитель на число запросов в день |
| `AI_FALLBACK_URL/KEY/MODEL` | Запасной LLM. Пусто = выключен |

### 3. Подключение настоящего Supabase

1. Создай проект на supabase.com, выполни в SQL Editor сначала
   `data/schema.sql`, затем `data/seed.sql`.
2. Если проект старый и словил `infinite recursion detected in policy for
   relation "classes"` — выполни `data/fix_rls_recursion.sql` один раз.
   В новых проектах `schema.sql` чинит это заранее.
3. Если база создавалась до появления школ и заявок — выполни
   `data/add_school_and_join_requests.sql`.
4. Впиши `SUPABASE_URL` / `SUPABASE_ANON_KEY` в `.env`, поставь
   `FORCE_DEMO=false`, прогони `node scripts/gen-config.mjs`.

Регистрация по email работает сразу — подтверждение почты по умолчанию
выключено, аккаунт входит в приложение мгновенно.

### 4. Настоящий ИИ на публичном деплое

Статический сайт не может спрятать ключ: всё, что попало в `config.js`, видно
через «просмотр кода». Поэтому `render-build.sh` намеренно пишет
`GEMINI_API_KEY: ''`, а реальный ключ живёт **только как секрет Edge Function**:

```bash
npx supabase login
npx supabase link --project-ref ТВОЙ_REF
npx supabase secrets set GEMINI_API_KEY=... GEMINI_MODEL=gemini-3.5-flash-lite \
  AI_FALLBACK_URL=https://api.groq.com/openai/v1/chat/completions \
  AI_FALLBACK_KEY=... AI_FALLBACK_MODEL=openai/gpt-oss-120b
npx supabase functions deploy ai
```

Команды запускай **из корня проекта** — там лежит `supabase/functions/ai/`.

Дальше задеплой статику на Render/Netlify/Vercel: Build Command указывает на
`render-build.sh`, который собирает `config.js` из переменных окружения
хостинга. **Не забудь `FORCE_DEMO=false`** в панели хостинга — иначе сайт
останется в демо-режиме и вход по email будет заблокирован.

## Как пользоваться (полный сценарий)

### Ученик
1. Онбординг: класс, предмет, цель (ЕНТ / олимпиада / подтянуть тему /
   школьная программа), срок цели, школа и — по желанию — **код класса от учителя**.
2. Диагностика на 11 вопросов → экран **«Рентген»** с найденным корнем.
3. **«Закрыть пробел»** — задания по корневой теме. При ошибке показывается
   разбор и кнопка «объясни проще».
4. С любого задания доступны **«Спросить Сократа»** и **«Объяснить своими словами»**.
5. В боковом меню: дашборд с прогрессом и слабыми местами, все темы, Рентген,
   Сократ, скан тетради, настройки (язык, режимы доступности, школа и класс).

### Учитель
1. **«Создать класс»** — у класса появляется **код для учеников**.
2. Ученик вводит этот код у себя → заявка приходит учителю.
3. Внутри класса: **«Принять» / «Отклонить»** заявки, **тепловая карта**
   (темы × ученики), карточки учеников с риск-статусом.
4. **«Радар риска»** — ИИ читает поведение класса и пишет короткие сигналы:
   кто теряет тему и почему, с цифрами.
5. **«Учитель-мультипликатор»** — вставь текст параграфа, получи тему с 10
   заданиями пяти уровней сложности и опубликуй её в граф класса.

### Репетиция показа
Поставь `FORCE_DEMO_AI=true` и прогони `node scripts/gen-config.mjs` — бэкенд
останется настоящим, а ИИ будет отвечать заготовками. Репетируй сколько угодно,
дневной лимит не тратится. Перед выступлением верни `false`.

Демо-датасет (`demo-data.js`) генерируется в памяти, бинарных фикстур в

## Модель ИИ

Используется **`gemini-3.5-flash-lite`** — по замерам на настоящих промптах
этого приложения, а не ради экономии:

| | 3.5-flash-lite | 3.5-flash | 3.6-flash |
|---|---|---|---|
| Конструктор модуля (10 заданий) | **5.4 с** | 16.8 с | 19–60 с |
| Остальные функции | **~1 с** | 4–7 с | 20–40 с |
| Качество на этих задачах | не хуже | не хуже | не хуже |
| Устойчивость к атаке на промпт | отбита | отбита | отбита |
| Дневной лимит free tier | высокий | ниже | ~20 запросов |

Проверялось: полнота модуля (10 заданий всех 5 уровней с ответами и разборами),
поиск реальной ошибки в объяснении ученика, вопрос по логике а не по числу,
казахский вывод, отказ выдать решение при прямой попытке взлома промпта.
`gemini-2.5-flash` и `gemini-2.5-flash-lite` больше не существуют (404).

**Восемь ИИ-функций:** `xray_summary`, `scan_notebook`, `tutor_reply`,
`comprehension_check`, `feynman_map`, `teacher_radar`, `module_builder`,
`explain_simpler`. Все с `responseSchema` — модель возвращает строгий JSON, а не
свободный текст.

## Надёжность ИИ на бесплатном тарифе

Весь слой ИИ (`assets/js/ai.js`) построен так, чтобы лимит нельзя было выжечь
случайно, а его исчерпание не выглядело как поломка:

- **Три уровня.** Gemini → запасной провайдер при 429 → офлайн-заготовки.
  Чтобы ученик остался без ответа, должны отвалиться оба провайдера сразу.
- **429 никогда не ретраится** — повтор при пустой квоте сжёг бы ещё один
  запрос. Ретраится только транзиентная ошибка, и только если первая попытка
  упала быстро.
- **Кэш по содержимому.** Ключ = функция + payload + язык + хэш изображения.
  Повторный вопрос стоит 0 запросов. Язык в ключе — чтобы казахский экран не
  проиграл русский ответ; хэш фото — чтобы два разных снимка тетради не
  схлопнулись в одну запись.
- **Дедупликация.** Три одновременных одинаковых вызова разделяют один промис и
  стоят один запрос.
- **Дневной бюджет** (`AI_DAILY_BUDGET`) — клиентский предохранитель против
  случайного цикла. Остаток виден в боковой панели.
- **Проверка «понял или угадал»** запускается только там, где угадать реально
  можно (варианты ответа) или ответ пришёл подозрительно быстро.
- **Честная маркировка.** Каждая ИИ-панель помечена источником: живой Gemini,
  кэш, запасная модель или заготовка. Заготовка **никогда** не выдаётся за ответ модели.

## Безопасность и приватность

- **Row Level Security на всех таблицах.** Проверено запросами: анонимный
  пользователь не видит ни одной строки из `profiles`, `attempts`, `mastery`,
  `diagnostics`, `goals`, `classes`, `class_members`, `ai_events`.
- **Нельзя писать за другого.** Попытка вставить попытку с чужим `user_id`
  отбивается на уровне политики — 403.
- **Ученики видны учителю только после подтверждения.** Заявка приходит со
  статусом `pending`; пока учитель не принял, профиль, попытки и mastery ученика
  ему недоступны.
- **Ключ ИИ не в браузере.** На публичном деплое `GEMINI_API_KEY` пустой в
  `config.js`, реальный ключ — секрет Edge Function. Запасной ключ тоже
  намеренно не пишется в публичный билд.
- **Анонимный ключ Supabase публичен по замыслу** — он рассчитан на клиентский
  доступ, защиту обеспечивает RLS, а не секретность ключа.
- **Защита от подмены промпта.** Системный промпт Сократа явно инструктирует
  игнорировать команды внутри сообщения ученика; проверено прямой атакой —
  модель отказывается выдать решение.

### Осознанные упрощения MVP (проговариваем честно)

- **Тепловая карта класса синтетическая.** Значения выводятся детерминированно
  из точности ученика — так строка карты никогда не противоречит его риск-карточке.
  На реальных данных сюда подставляется `mastery` из БД.
- **Разметка ошибки на фото — оценка по номеру строки**, а не настоящий
  bounding-box. Для точных координат нужен отдельный vision-проход с запросом полигонов.
- **Синхронизация mastery — last-write-wins.** Разрешение конфликтов между
  устройствами не реализовано.
- **Названия тем в БД только на русском** (`title_kk` в сиде не заполнен).
  Интерфейс и ответы ИИ переведены полностью, названия узлов — нет.
- **Дневной бюджет ИИ хранится в localStorage** — он общий на браузер, а не на
  аккаунт, и сбрасывается при очистке данных сайта. Это предохранитель, а не учёт.

## Примечания

- **Версию кэша в `sw.js` нужно бампать при каждом деплое**, который меняет файлы
  оболочки. `activate` удаляет кэши с другим именем — новое имя и есть то, что
  сгоняет вернувшихся посетителей со старой сборки. Стратегия —
  stale-while-revalidate: страница отвечает мгновенно из кэша и обновляет его в
  фоне, поэтому одной перезагрузки достаточно.
- **Внешних зависимостей во фронтенде нет.** `supabase-js` подгружается
  динамическим импортом только на реальном пути — на демо-пути и офлайн он не
  запрашивается вовсе.
- **Глубина в графе = время.** Верхний слой — то, что проходят сейчас; чем
  глубже узел, тем раньше его учили. Поэтому «спускаемся к корню» — буквальное
  описание того, что видно на экране.
- `create_all` здесь нет: схема применяется SQL-файлами вручную. Если меняешь
  структуру уже созданной базы — выполняй `ALTER TABLE` в Supabase SQL Editor.
